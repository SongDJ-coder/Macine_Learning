# 📘 3장 회귀 알고리즘과 모델 규제

## 03-1 k-최근접 이웃 회귀

### 분류(classification) vs 회귀(regression)

| | 정답의 성격 | 예시 | k-NN에서 예측 방식 |
|---|---|---|---|
| **분류** (1~2장) | 범주(카테고리), 예: 0 또는 1 | 도미냐 빙어냐 | 가까운 k개의 **다수결 투표** |
| **회귀** (3장) | 연속적인 숫자값 | 생선의 무게(g) | 가까운 k개의 **평균값** |

거리 계산으로 가까운 이웃 k개를 찾는 원리(`fit`=암기, `predict`=거리 계산)는 동일함.
마지막 단계(다수결 vs 평균)만 다름. 그래서 사이킷런에서도 분류는
`KNeighborsClassifier`, 회귀는 `KNeighborsRegressor`로 클래스가 나뉨.

### k-NN 회귀의 예측 방식 — "가까운 이웃들의 평균"

거리 계산으로 가까운 k개를 찾는 것까지는 분류와 동일. 다수결 대신 **그 k개의 정답값을
평균**내서 예측값으로 씀.

```
새로운 생선 길이 = 25일 때

1. 훈련 데이터에서 길이가 25에 가까운 순서로 k개(기본 5개) 뽑음
2. 그 5마리의 실제 무게 확인 (예: 90g, 100g, 95g, 110g, 105g)
3. 평균 계산 → (90+100+95+110+105)/5 = 100g
4. 예측 결과: 100g
```

> [!warning] 태생적 한계
> 평균을 내는 방식이라, 훈련 데이터에 없던 극단값(훈련 데이터 최대 길이보다 훨씬 큰
> 생선 등)은 잘 예측 못함. 아무리 커도 "가장 가까운 이웃"은 여전히 훈련 데이터
> 안에서만 뽑히므로, 예측값이 훈련 데이터 범위를 못 벗어나고 과소평가됨.

### 과대적합(overfitting)과 k값의 관계

> [!tip] "과대적합이면 k를 늘려라"의 이유
> `k`는 "예측할 때 개별 데이터에 얼마나 민감하게 반응할지"를 조절하는 값.
>
> - **k가 작으면(k=1 등)**: 이웃 1개 값을 거의 그대로 씀 → 그 이웃이 하필 이상치면
>   예측이 통째로 흔들림. 훈련 점수는 매우 높은데 테스트 점수는 낮음 → **과대적합**
>   (훈련 데이터를 "외운" 것에 가까움).
> - **k가 크면**: 더 많은 이웃을 평균내므로 이상치 하나의 영향이 희석되고, 전체
>   흐름을 따라가는 부드러운 예측이 됨 → 일반화 성능 향상.
> - **k가 너무 크면(전체 데이터 개수만큼)**: 어디서 예측하든 항상 전체 평균 하나만
>   나옴 → 반대로 너무 단순해서 **과소적합**.
>
> 즉 k는 복잡도 손잡이: 작을수록 훈련 데이터에 딱 맞춰 복잡해지고(과대적합 위험),
> 클수록 뭉뚱그려 단순해짐(과소적합 위험). 과대적합 신호(훈련↑, 테스트↓↓)가 보이면
> k를 키워서 완화함.

### 🔑 핵심 원리 — 사이킷런은 훈련 데이터를 항상 2차원으로 요구함

> [!warning] 규칙
> 특성이 몇 개든 상관없이, `fit()`/`predict()`에 넣는 X는 반드시
> `(샘플 개수, 특성 개수)` 형태의 **2차원 배열**이어야 함. 1차원 배열은
> "샘플이 여러 개인지 특성이 여러 개인지" 구분이 안 돼서 아예 거부당함.

> [!question] 추가 질문
> [[extra/ch03-2차원배열-예시|왜 하필 2차원이어야 하는지, 실제 숫자 예시로]]

**1~2장에서는 문제가 안 됐던 이유**: `fish_data`가 처음부터 `[[길이,무게], ...]`로
특성이 2개라 자연스럽게 `(49, 2)`였음.

**3장에서 처음 문제가 되는 이유**: `perch_length` 혼자만 씀(특성 1개) → 원래
`(56,)` 1차원. `train_test_split`은 모양을 안 바꾸고 그대로 나누기만 하므로
`train_input`도 여전히 1차원 `(42,)`. 모델에 넣기 직전에 직접 2차원으로 바꿔줘야 함:

```python
train_input = train_input.reshape(-1, 1)
test_input = test_input.reshape(-1, 1)
```

- `1`: 열(특성) 개수를 1개로 고정
- `-1`: 행(샘플) 개수는 넘파이가 전체 원소 수 ÷ 1로 자동 계산
  → 개수를 직접 안 세도 되고, 데이터 크기가 달라져도(훈련 42개/테스트 14개) 같은 코드 재사용 가능

값 자체는 전혀 바뀌지 않음 — `[10,12,5,13,8,3]`(1차원)이
`[[10],[12],[5],[13],[8],[3]]`(2차원)로 **포장만** 바뀌는 것.
