# 📘 3장 회귀 알고리즘과 모델 규제

## 03-1 k-최근접 이웃 회귀

### 분류(classification) vs 회귀(regression)

| | 정답의 성격 | 예시 | k-NN에서 예측 방식 |
|---|---|---|---|
| **분류** (1~2장) | 범주(카테고리), 예: 0 또는 1 | 도미냐 빙어냐 | 가까운 k개의 **다수결 투표** |
| **회귀** (3장) | 연속적인 숫자값 | 생선의 무게(g) | 가까운 k개의 **평균값** |

거리 계산으로 가까운 이웃 k개를 찾는 원리(`fit`=암기, `predict`=거리 계산)는 동일함.
마지막 단계(다수결 vs 평균)만 다름. 그래서 사이킷런에서도 분류는
`KNeighborsClassifier`, 회귀는 `KNeighborsRegressor`로 클래스가 나뉨.

### k-NN 회귀의 예측 방식 — "가까운 이웃들의 평균"

거리 계산으로 가까운 k개를 찾는 것까지는 분류와 동일. 다수결 대신 **그 k개의 정답값을
평균**내서 예측값으로 씀.

```
새로운 생선 길이 = 25일 때

1. 훈련 데이터에서 길이가 25에 가까운 순서로 k개(기본 5개) 뽑음
2. 그 5마리의 실제 무게 확인 (예: 90g, 100g, 95g, 110g, 105g)
3. 평균 계산 → (90+100+95+110+105)/5 = 100g
4. 예측 결과: 100g
```

> [!warning] 태생적 한계
> 평균을 내는 방식이라, 훈련 데이터에 없던 극단값(훈련 데이터 최대 길이보다 훨씬 큰
> 생선 등)은 잘 예측 못함. 아무리 커도 "가장 가까운 이웃"은 여전히 훈련 데이터
> 안에서만 뽑히므로, 예측값이 훈련 데이터 범위를 못 벗어나고 과소평가됨.

### 과대적합(overfitting)과 k값의 관계

> [!tip] "과대적합이면 k를 늘려라"의 이유
> `k`는 "예측할 때 개별 데이터에 얼마나 민감하게 반응할지"를 조절하는 값.
>
> - **k가 작으면(k=1 등)**: 이웃 1개 값을 거의 그대로 씀 → 그 이웃이 하필 이상치면
>   예측이 통째로 흔들림. 훈련 점수는 매우 높은데 테스트 점수는 낮음 → **과대적합**
>   (훈련 데이터를 "외운" 것에 가까움).
> - **k가 크면**: 더 많은 이웃을 평균내므로 이상치 하나의 영향이 희석되고, 전체
>   흐름을 따라가는 부드러운 예측이 됨 → 일반화 성능 향상.
> - **k가 너무 크면(전체 데이터 개수만큼)**: 어디서 예측하든 항상 전체 평균 하나만
>   나옴 → 반대로 너무 단순해서 **과소적합**.
>
> 즉 k는 복잡도 손잡이: 작을수록 훈련 데이터에 딱 맞춰 복잡해지고(과대적합 위험),
> 클수록 뭉뚱그려 단순해짐(과소적합 위험). 과대적합 신호(훈련↑, 테스트↓↓)가 보이면
> k를 키워서 완화함.

### 🔑 핵심 원리 — 사이킷런은 훈련 데이터를 항상 2차원으로 요구함

> [!warning] 규칙
> 특성이 몇 개든 상관없이, `fit()`/`predict()`에 넣는 X는 반드시
> `(샘플 개수, 특성 개수)` 형태의 **2차원 배열**이어야 함. 1차원 배열은
> "샘플이 여러 개인지 특성이 여러 개인지" 구분이 안 돼서 아예 거부당함.

> [!question] 추가 질문
> [[extra/ch03-2차원배열-예시|왜 하필 2차원이어야 하는지, 실제 숫자 예시로]]

**1~2장에서는 문제가 안 됐던 이유**: `fish_data`가 처음부터 `[[길이,무게], ...]`로
특성이 2개라 자연스럽게 `(49, 2)`였음.

**3장에서 처음 문제가 되는 이유**: `perch_length` 혼자만 씀(특성 1개) → 원래
`(56,)` 1차원. `train_test_split`은 모양을 안 바꾸고 그대로 나누기만 하므로
`train_input`도 여전히 1차원 `(42,)`. 모델에 넣기 직전에 직접 2차원으로 바꿔줘야 함:

```python
train_input = train_input.reshape(-1, 1)
test_input = test_input.reshape(-1, 1)
```

- `1`: 열(특성) 개수를 1개로 고정
- `-1`: 행(샘플) 개수는 넘파이가 전체 원소 수 ÷ 1로 자동 계산
  → 개수를 직접 안 세도 되고, 데이터 크기가 달라져도(훈련 42개/테스트 14개) 같은 코드 재사용 가능

값 자체는 전혀 바뀌지 않음 — `[10,12,5,13,8,3]`(1차원)이
`[[10],[12],[5],[13],[8],[3]]`(2차원)로 **포장만** 바뀌는 것.

## 03-2 선형 회귀

### k-NN 회귀의 한계 → 선형 회귀로

k-NN은 평균을 내는 방식이라 훈련 데이터 범위를 벗어난 값(예: 매우 큰 생선)을 못
예측함(위 경고 참고). **선형 회귀**는 대신 `무게 = w×길이 + b` 같은 **직선/곡선
수식 자체**를 찾아내므로, 범위 밖도 수식을 따라 자연스럽게 연장해서 예측 가능함.

```python
from sklearn.linear_model import LinearRegression
lr = LinearRegression()
lr.fit(train_input, train_target)
print(lr.coef_, lr.intercept_)   # coef_=기울기(w), intercept_=절편(b)
```

### 다항 회귀 — 곡선으로 피팅

실제 길이-무게 관계는 완전한 직선이 아니라 **곡선**에 가까움. `길이²` 항을
추가하면 곡선 형태로 피팅 가능:

```python
train_poly = np.column_stack((train_input ** 2, train_input))
test_poly = np.column_stack((test_input ** 2, test_input))
lr.fit(train_poly, train_target)
```
`LinearRegression` 자체는 "이게 2차식이다"를 전혀 모름 — 그냥 열 2개짜리 평범한
선형 회귀를 하는 것뿐인데, 특성을 `[길이², 길이]`로 미리 가공해서 넣었기 때문에
결과 수식이 우연히 2차 함수(곡선) 형태가 되는 것. "트릭은 `fit()`이 아니라
특성 설계에 있음."

### 🔑 최소제곱법 — fit()이 실제로 계수를 찾는 방법

`LinearRegression.fit()`은 "오차 제곱합이 최소가 되는 w, b"를 **행렬 공식으로
한 번에 계산**함 (시행착오 없음). 자세한 수학적 유도(미분→정규방정식→행렬형태,
시각화 포함):
[[extra/ch03-최소제곱법-유도|최소제곱법 수학적 유도]]

> [!tip] 핵심만 요약
> ```
> w = (XᵀX)⁻¹ Xᵀy
> ```
> 이 공식은 특성이 몇 개든(1개든 55개든) 그대로 적용됨 — 행렬 크기만 커질 뿐 원리는 동일.

## 03-3 특성 공학과 규제

### 다중 회귀 — 특성을 여러 개 쓰기

길이 하나 대신 길이·높이·두께 3개를 다 쓰면, 모델이 조절할 수 있는 계수가 늘어나서
더 정교한 예측이 가능해짐 (단, 너무 늘리면 과대적합 위험 — 아래 참고).

```python
import pandas as pd
df = pd.read_csv('https://bit.ly/perch_csv_data')   # 길이/높이/두께 3개 열
perch_full = df.to_numpy()
```

> **커널 재시작**. 그래도 안 되면 CSV 내용을 직접 배열로 입력해서 우회 가능.

### 사이킷런의 변환기(Transformer) — `PolynomialFeatures`

지금까지 쓴 `KNeighborsRegressor`, `LinearRegression`은 **추정기(모델)**:
`fit`(학습) → `predict`(예측). 반면 `PolynomialFeatures`는 **변환기**:
`fit`(변환 규칙 파악) → `transform`(데이터 변형 실행) — 정답을 예측하는 게 아니라
**입력 데이터 자체를 가공**해서 돌려줌.

```python
from sklearn.preprocessing import PolynomialFeatures
poly = PolynomialFeatures(degree=2, include_bias=False)  # degree 기본값=2
poly.fit(train_input)          # "특성이 3개구나" 파악만 함 (학습 아님)
train_poly = poly.transform(train_input)   # 실제 변환 실행
test_poly = poly.transform(test_input)     # fit은 train만, test는 transform만 재사용
```
길이·높이·두께 3개 → 원래 특성 3개 + 제곱항 3개 + 교차항 3개 = **9개**로 자동 확장
(`degree=2`까지의 모든 조합). `poly.fit()`은 train에서만 한 번 하고, 그 "규칙"을
test에도 그대로 `transform()`만 적용 — 표준화 때 train의 mean/std를 test에
재사용했던 것과 같은 원칙.

### 🔑 왜 규제 전에 꼭 스케일을 맞춰야 하는가

> [!warning] 핵심 원리
> 규제(Ridge/Lasso)는 "오차 + λ×(계수 크기)"를 최소화함. 근데 계수의 필요한 크기는
> 특성의 단위(스케일)에 따라 원래부터 다름 — 스케일 큰 특성은 작은 계수로 충분하고,
> 스케일 작은 특성은 큰 계수가 필요함. 표준화 없이 규제하면 "진짜 안 중요한 특성"이
> 아니라 "그냥 단위가 작아서 계수가 커진 특성"을 불공평하게 처벌하게 됨.
>
> **규제 없는 일반 회귀는 스케일 영향 없음** (조인트 최적화가 알아서 보정) — 스케일이
> 문제되는 건 오직 규제의 "계수 크기 페널티" 항 때문.

자세한 예시(단위 바꾸면 페널티가 왜 100배씩 달라지는지):
[[extra/ch03-스케일과규제|스케일과 규제의 관계]]

### Ridge (L2 규제) — 행렬 공식 그대로 확장됨

```
손실 = (y-Xw)ᵀ(y-Xw) + λwᵀw
미분해서 0으로 놓으면 → w = (XᵀX + λI)⁻¹ Xᵀy
```
기존 정규방정식에서 `(XᵀX)⁻¹` 자리가 `(XᵀX + λI)⁻¹`로 바뀐 것뿐 — 대각선에 λ를
더해주는 것. 부수 효과로, 특성이 샘플보다 많아 `XᵀX`가 역행렬이 없는(특이행렬)
경우에도 **항상 역행렬이 존재하게** 만들어줌 (수치 안정화).

```python
from sklearn.linear_model import Ridge
ridge = Ridge(alpha=1)   # alpha = λ (규제 강도)
ridge.fit(train_scaled, train_target)
```

### Lasso (L1 규제) — 절댓값 페널티, 반복 계산

```
손실 = (y-Xw)ᵀ(y-Xw) + λΣ|w|
```
절댓값은 `w=0`에서 미분이 안 됨(뾰족하게 꺾임) → Ridge처럼 공식 한 방으로 못 풀고,
좌표하강법 등 **반복적으로 조금씩 계수를 조정**해가며 최적값을 찾음.

```python
from sklearn.linear_model import Lasso
lasso = Lasso(alpha=1)
lasso.fit(train_scaled, train_target)
```
