# degree=5로 올렸을 때 책과 다른 결과가 나온 이유 (라이브러리 버전차이 실측)

> [[ch03|← 3장 원리 노트로 돌아가기]]

**상황**: `PolynomialFeatures(degree=5)`로 특성을 55개까지 늘려서
`LinearRegression`을 돌렸는데, 책은 극심한 과대적합(훈련 ≈1.0, 테스트 ≈-144.4)을
보여주는 게 포인트인데, 실제로는 훈련 0.9954 / 테스트 0.978로 **전혀 과대적합이
안 보임.**

## 원인 분석

`train_poly.shape = (42, 55)` — **훈련 샘플(42개)보다 특성(55개)이 더 많음.**
이런 경우 `XᵀX`는 수학적으로 **특이행렬(singular)**이라 역행렬이 존재하지 않음
(연립방정식의 미지수가 식보다 많은 상황과 같음).

사이킷런은 이럴 때 에러를 내는 대신, **SVD(특잇값 분해) 기반 최소제곱법**으로
"그나마 가장 적절한" 근사해를 계산함(`scipy.linalg.lstsq`). 근데 이 근사 계산의
구체적인 동작(수치 안정성, rank 판정 기준 등)이 **numpy/scipy 버전마다 미묘하게
다름.**

- 책이 쓰인 시점의 구버전 → 이 근사가 매우 불안정해서 테스트 점수가 `-144`까지
  폭망 (책이 보여주려던 "극심한 과대적합" 예시)
- 최신 버전(2026년 기준 pip 설치) → SVD 계산이 더 안정적으로 개선돼서, 같은 코드인데도
  그렇게까지 망가지지 않음

## 직접 재현해서 검증함

제 환경(numpy 2.4.6, scipy 1.17.1, sklearn 1.9.1 — 사용자님 환경과 거의 동일 시점에
설치)에서 책과 동일한 코드로 재현해보니:
```
train score: 0.9953852031717547
test score: 0.9780184172674875
```
→ 사용자님이 받은 값과 정확히 일치. **코드 버그 아니고, 버전 차이가 원인인 걸
확인함.**

> [!tip] 결론
> 개념(특성이 샘플 수보다 많아지면 수치적으로 불안정해지고 과대적합 위험이 커짐)은
> 여전히 유효하고, 다음 절(규제)로 이어지는 이유도 똑같이 성립함. 다만 "극단적으로
> 망가지는 숫자(-144)" 자체는 라이브러리 버전 차이 때문에 최신 환경에서는 그대로
> 재현되지 않을 뿐임. 코드 고칠 필요 없음.
