# column_stack 순서를 바꿨는데 coef_가 그대로 나온 이유 (디버깅 사례)

> [[ch03|← 3장 원리 노트로 돌아가기]]

**상황**: `train_poly = column_stack((train_input**2, train_input))`(책 순서)를
`column_stack((train_input, train_input**2))`로 순서를 바꿔봤는데, `lr.coef_`가
**책이랑 완전히 똑같은 순서**로 나옴. 이론상 순서를 바꾸면 계수 위치도 바뀌어야
하는데?

### 이론적으로 맞아야 하는 결과

실제로 계산해보면:
```
책 순서(길이², 길이): coef_ = [ 1.01433211, -21.55792498]
순서 바꾼 경우(길이, 길이²): coef_ = [-21.55792498,  1.01433211]   ← 위치가 뒤바뀌어야 함
```
데이터 자체가 정해주는 두 숫자(`1.014`, `-21.558`)는 같지만, **배열 안 위치는
입력 열 순서를 따라가야 함.**

### 실제로는 책과 완전히 동일하게 나왔던 이유

→ **주피터 노트북에서 셀을 수정했는데 다시 실행을 안 한 것(또는 실행 순서가
꼬인 것)**이 원인이었음. `train_poly`를 만드는 셀을 고쳤어도, 그 셀을 재실행하지
않고 `lr.fit()` 셀만 실행하면 **예전 변수값이 그대로 남아있음.**

> [!warning] 주피터 노트북 공통 함정
> 셀은 "위에서 아래로 순서대로"가 아니라 **"내가 실행 버튼을 누른 순서대로"**
> 상태가 쌓임. 코드를 고쳤으면 반드시 그 셀부터 다시 실행해야 하고, 애매하면
> `Restart Kernel + Run All`로 처음부터 깨끗하게 재실행해서 확인하는 게 안전함.

### 확인하는 법
```python
print(train_poly[:3])   # 왼쪽 열이 큰 숫자(제곱값)인지 작은 숫자(원값)인지로 순서 판별
```
