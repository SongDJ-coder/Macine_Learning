# 왜 [3:4]는 2차원이고, indexes도 2차원인가

> [[ch04|← 4장 원리 노트로 돌아가기]]

## 1. 정수 인덱싱 vs 슬라이스 인덱싱

> [!tip] 규칙 하나
> **정수 하나로 인덱싱하면 그 차원이 사라지고, 슬라이스(`:`)로 인덱싱하면 그 차원이 유지된다.**

```
arr = [[1, 2],          arr[2]    → [5, 6]       shape (2,)    ← 1차원. "행" 개념이 사라짐
       [3, 4],          arr[2:3]  → [[5, 6]]     shape (1, 2)  ← 2차원. "행이 1개인 표"로 남음
       [5, 6],
       [7, 8]]   shape (4, 2)
```

비유하면:
- `arr[2]` = "2번 책을 줘" → 책장에서 책을 **꺼낸다**. 결과는 책 한 권(1차원)
- `arr[2:3]` = "2번부터 3번 직전까지의 **구간**을 줘" → 책이 1권뿐이어도 결과는 여전히 책장(2차원)

그래서 `test_scaled[3:4]`는 샘플 1개짜리지만 `(1, 5)` 모양을 유지한다. 사이킷런은 입력을 항상
2차원으로 요구하므로, `[[ ]]`로 감싸는 대신 슬라이스로 같은 효과를 낸 것이다.

## 2. kneighbors의 출력도 2차원인 이유

사이킷런 함수는 **질문(쿼리) 여러 개를 한 번에** 처리하도록 만들어져 있다. 그래서 출력도
항상 `(질문 개수, k)` 모양이다.

```
kn.kneighbors(test_scaled[3:4])   # 질문 1개
indexes.shape → (1, 3)
                 ↑  ↑
                 │  └─ k=3개 이웃의 인덱스
                 └──── 질문 1개

kn.kneighbors(test_scaled[3:6])   # 질문 3개
indexes → [[이웃, 이웃, 이웃],   ← 1번째 질문의 답
           [이웃, 이웃, 이웃],   ← 2번째 질문의 답
           [이웃, 이웃, 이웃]]   ← 3번째 질문의 답
```

질문을 1개만 했으니 결과는 "행이 1개뿐인 2차원"이고, `indexes[0]`으로 그 유일한 행을 꺼내야
이웃 번호 3개를 1차원으로 얻는다. `predict()`가 샘플 개수만큼 결과를 돌려주는 것과 같은 패턴이다.
