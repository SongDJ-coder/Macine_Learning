# 왜 하필 2차원이어야 하는가 — 실제 숫자 예시

> [[ch03|← 3장 원리 노트로 돌아가기]]

**Q: 사이킷런 훈련 세트가 2차원 배열이어야 한다는 게 정확히 무슨 뜻이야? 감이 안 와.**

같은 숫자 6개로 완전히 다른 두 가지 상황을 만들 수 있다는 걸로 확인하면 이해가 쉬움.

```python
data = [10, 12, 5, 13, 8, 3]   # 그냥 숫자 6개, 1차원 (6,)
```

**상황 A — "생선 6마리, 각자 길이 1개씩"**
```python
np.array(data).reshape(6, 1)
# [[10],
#  [12],
#  [5],
#  [13],
#  [8],
#  [3]]
```
→ `(6, 1)`: 샘플 6개, 특성 1개짜리. 우리가 원하는 상황.

**상황 B — "생선 1마리, 근데 특성이 6개(길이·높이·무게 등등)"**
```python
np.array(data).reshape(1, 6)
# [[10, 12, 5, 13, 8, 3]]
```
→ `(1, 6)`: 샘플 딱 1개, 그 1마리를 6가지 특성으로 묘사.

**핵심**: A와 B는 완전히 같은 숫자 6개, 같은 순서인데 의미가 정반대임. A는
"서로 다른 생선 6마리 각각을 예측", B는 "생선 1마리를 여러 특성으로 예측"이라는
전혀 다른 문제가 됨.

> [!warning] 그래서 1차원을 거부하는 이유
> `data`를 그냥 1차원(`(6,)`)으로 주면, 사이킷런은 이게 A인지 B인지 판단할
> 방법이 없어서 아예 에러를 내버림. `reshape`로 **명확하게 2차원으로
> "행이 샘플이다"라고 못박아줘야만** 제대로 해석 가능함.

### 잘못 reshape하면 생기는 문제
`reshape(-1, 2)`로 잘못 했다면 `[[10,12],[5,13],[8,3]]`(3행 2열)이 됨 — 서로
다른 생선 두 마리(10, 12)가 한 샘플의 특성 2개인 것처럼 잘못 엮여버림. 게다가
정답 배열은 여전히 6개인데 샘플은 3개로 인식되니 **개수부터 안 맞아서** 에러남.

지금 우리 상황(길이 하나하나가 서로 다른 생선)에선 항상 `reshape(-1, 1)`(상황 A)가 정답.
