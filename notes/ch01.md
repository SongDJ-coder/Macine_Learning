## 🐟 01-3 도미 vs 빙어 분류 — k-최근접 이웃(k-NN)

### 📌 문제 설정

생선의 **길이**와 **무게**, 두 특성(feature)으로 도미(bream) / 빙어(smelt)를 구분한다.

| | 길이 | 무게 | 산점도 위치 |
|---|---|---|---|
| 🐟 도미(bream) | 길다 | 무겁다 | 오른쪽 위 |
| 🐠 빙어(smelt) | 짧다 | 가볍다 | 왼쪽 아래 |

두 무리가 겹치지 않는 영역으로 뭉쳐 있기 때문에 분류가 가능하다.

### ⚙️ k-NN 동작 원리 — "암기 후 다수결"

```
① 훈련 (fit)
   fit(fish_data, fish_target)
        │
        ▼
   데이터를 그대로 통째로 저장 (규칙 계산 없음 → 매우 빠름)


② 예측 (predict)
   새로운 점 입력
        │
        ▼
   저장된 모든 점과 거리 계산 (유클리드 거리)
        │
        ▼
   가장 가까운 k개 선택 (기본값 k=5)
        │
        ▼
   k개 이웃의 라벨을 다수결 투표
        │
        ▼
   예측 결과 (예: 5개 중 4개가 도미 → "도미")
```

> [!tip] 왜 이게 통하는가
> "비슷한 특성을 가진 데이터는 그래프 상에서도 가까이 모여 있다"는 가정에 기반.
> 도미/빙어가 산점도에서 서로 다른 영역에 뭉쳐 있었기 때문에, 새 점의 가까운
> 이웃들도 대부분 같은 종에 속해 분류가 잘 맞는다.

> [!warning] 한계 (책에서 잘 안 짚는 부분)
> - **느려짐**: 예측마다 저장된 전체 데이터와 거리를 다시 계산 → 데이터가 많아지면 느려짐
>   ("모델 학습" 아니라 매 예측 시 전체를 훑는 lazy learning 방식)
> - **스케일 문제**: 길이(수십)·무게(수백~수천) 값의 범위 차이 → 거리 계산이 무게 쪽에 치우침
>   → [[ch02|2장 데이터 전처리]]에서 표준화로 해결

#### 💬 추가 질문

**Q: k-NN이 어차피 예측할 때마다 전체 데이터와 거리 계산을 하는 거면, `fit()`으로 굳이 "학습"할 필요가 있나?**

A: 두 가지 이유가 있음.
1. **API 일관성** — 사이킷런은 모든 모델을 `fit → predict` 패턴으로 통일해둠. 다른 모델은 실제로
   가중치/규칙을 계산하지만 k-NN은 저장만 함. 그래도 인터페이스를 맞춰야 모델을 바꿔 껴도
   코드가 그대로 동작함.
2. **fit()이 실제로 하는 일이 있음** — 데이터를 리스트에 저장만 하는 게 아니라, 예측 속도를
   높이기 위한 탐색 자료구조(KD-tree, Ball-tree)를 이 시점에 미리 만들어둠. 데이터가 적을 땐
   차이가 없지만, 대량 데이터에서는 이게 있어야 매번 전체와 거리 계산하는 걸 피할 수 있음.

→ 정리: k-NN에서 "학습"은 규칙을 배우는 게 아니라, 나중 예측을 빠르게 하려는 준비 단계에 가까움.
