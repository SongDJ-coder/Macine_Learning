# ☁️ Claude Code 클라우드 환경 사용법

## 클라우드 세션이란

**Anthropic 서버에 나만 쓰는 임시 컴퓨터를 하나 빌려서, 거기서 Claude가 작업하는 방식.**
이 공부에 쓰는 세션의 사양(직접 확인한 값):

| 항목 | 값 |
|---|---|
| OS | Ubuntu 24.04 (리눅스) |
| CPU / 메모리 | 4코어 / 15GB |
| GPU | **없음** |

## 세션 하나의 생애주기

```
[새 세션 시작]
     ↓
① 환경 설정대로 컨테이너(임시 컴퓨터) 생성
   - 네트워크 정책 적용
   - API 자격 증명 주입
     ↓
② 설정 스크립트 실행 (저장소 clone, 패키지 설치)
     ↓
③ GitHub 저장소를 /home/user/Macine_Learning 에 clone
     ↓
④ Claude Code 시작 → CLAUDE.md 읽음 → 대화
     ↓
[세션 종료 또는 한동안 사용 안 함]
     ↓
⑤ 컨테이너 삭제 → push한 것만 GitHub에 남고 나머지는 전부 사라짐
```
②와 ③의 순서는 확실하지 않아서, 설정 스크립트는 저장소 폴더에 의존하지 않는 경로를 쓴다.

> [!warning] 컨테이너는 일회용
> 매번 새로 만들어지고 끝나면 버려진다. 그래서
> 1. 남기고 싶은 건 **반드시 push**하고
> 2. 매번 필요한 준비는 **설정 스크립트로 자동화**한다.

## 클라우드 vs 로컬

| | 클라우드 | 로컬 (내 컴퓨터) |
|---|---|---|
| 환경 문제 | 깨끗한 리눅스라 거의 안 생김 | 내 컴퓨터 설정에 따라 생김 (Workspace Trust, cp949, SSL 문제가 전부 로컬 쪽이었음) |
| 접속 | 폰·다른 컴퓨터 어디서든 같은 세션 | 그 컴퓨터 앞에서만 |
| 컴퓨터 꺼도 되나 | 됨 (서버에서 계속 돎) | 끄면 멈춤 |
| 여러 작업 동시에 | 세션 여러 개를 따로 띄움 | 내 컴퓨터 자원을 나눠 씀 |
| 내 파일 접근 | 못 봄 → push해야 보임 | 바로 봄 |
| 데이터 유지 | push 안 하면 사라짐 | 계속 남음 |
| GPU | 없음 | 내장 그래픽이라 마찬가지 |

> [!tip] 이 공부의 역할 분담
> 노트북 실습은 **로컬 VS Code**에서, 원리 설명·코드 검증·재현·노트 정리는 **클라우드 세션**에서 한다.
> 둘을 **GitHub**가 이어준다.

## 환경 설정 3가지

환경 설정은 세션 상단 제목 줄의 **클라우드 환경 메뉴 → 편집**에서 바꾼다.
"클라우드 환경 추가"는 설정이 다른 환경을 하나 더 만드는 것이고, 보통은 기존 환경을 편집하면 된다.

| 항목 | 작동 방식 | 쓸 일 |
|---|---|---|
| **네트워크 액세스** | 모든 인터넷 연결이 프록시를 거치고, 프록시가 허용된 곳인지 검사함. "신뢰됨" = GitHub, PyPI 같은 개발용 사이트 허용 | 막힌 사이트가 생기면 허용 목록에 추가 |
| **API 자격 증명** | 키를 환경에 저장 → 세션이 값을 직접 보지 않고 API 호출 가능 | 개정판 10장 OpenAI API 예제. **키를 채팅에 붙여넣지 말 것** |
| **설정 스크립트** | 새 세션마다 Claude Code보다 먼저 자동 실행. 저장 후 여는 세션부터 적용 | 저장소 clone, 패키지 설치 자동화 |

## 스크립트란

**명령어를 순서대로 적어둔 파일.** 터미널에 한 줄씩 치는 대신, 적어둔 걸 위에서부터 차례로 자동 실행한다.
요리 레시피처럼 "1번 하고, 2번 하고, 3번 해라"를 미리 적어두는 것.

- **bash**: 리눅스 터미널의 명령어 언어 (Windows의 PowerShell 같은 것)
- 로컬에서 친 `python -m venv venv`, `pip install`, `git pull`도 전부 셸 명령어다. 스크립트는 이걸 파일에 모아둔 것

## 이 저장소의 설정 스크립트

파일: [setup/cloud_setup.sh](../../setup/cloud_setup.sh) — 이 내용을 환경의 "설정 스크립트" 칸에 붙여넣는다.

```bash
REF_DIR=/home/user/rickiepark     # 책 공식 코드 저장소 위치
VENV_DIR=/home/user/ml-venv       # 가상환경 위치

mkdir -p "$REF_DIR"
for repo in hg-mldl hg-mldl2; do
  if [ ! -d "$REF_DIR/$repo" ]; then
    GIT_LFS_SKIP_SMUDGE=1 git clone --depth 1 "https://github.com/rickiepark/$repo" "$REF_DIR/$repo" \
      || echo "[setup] $repo clone 실패 (세션은 계속 진행)"
  fi
done

if [ ! -x "$VENV_DIR/bin/python" ]; then
  python3 -m venv "$VENV_DIR"
fi
"$VENV_DIR/bin/pip" install -q --upgrade pip
"$VENV_DIR/bin/pip" install -q numpy pandas matplotlib scikit-learn \
  || echo "[setup] 패키지 설치 실패 (세션은 계속 진행)"
```

| 코드 | 의미 |
|---|---|
| `#!/bin/bash` | "이 파일은 bash로 실행해라"라는 표시 |
| `REF_DIR=...` | 경로를 변수에 저장. `"$REF_DIR"`로 꺼내 씀. 경로를 바꾸려면 이 줄만 고치면 됨 |
| `mkdir -p` | 폴더 만들기. `-p` = 이미 있으면 그냥 넘어감 |
| `for repo in A B; do ... done` | A, B를 하나씩 `repo`에 넣어 같은 작업 반복 |
| `if [ ! -d "..." ]; then ... fi` | 그 폴더가 **없으면**만 실행 (`!` = 아니면, `-d` = 폴더 있음) |
| `git clone --depth 1` | 과거 기록 없이 최신본만 빠르게 복사 |
| `GIT_LFS_SKIP_SMUDGE=1` | 대용량 파일 처리를 건너뛰어 clone 실패를 막음 |
| `\|\| echo "..."` | 앞 명령이 **실패하면** 메시지만 출력하고 넘어감 (세션 시작이 막히지 않게) |
| `python3 -m venv` | 가상환경 만들기 (로컬의 `python -m venv venv`와 같음) |
| `"$VENV_DIR/bin/pip" install` | 그 가상환경의 pip로 설치. 활성화 없이 경로를 직접 지정 |
| `-q` | 설치 로그를 조용히(quiet) |

> [!tip] 설계 포인트
> "이미 있으면 건너뛰기"라서 여러 번 실행해도 안전하다. (테스트 결과: 첫 실행 약 37초, 재실행 1초 이내)

**늘리는 법**: 7장 딥러닝부터는 스크립트 맨 아래의 `tensorflow torch` 줄 주석(`#`)을 풀면 된다.
다른 참고 저장소가 필요하면 `for repo in ...` 목록에 이름만 추가한다.

**확인**: 새 세션에서 `ls /home/user/rickiepark`에 두 폴더가 보이면 성공.

## 왜 항상 git pull을 해야 하나

복사본이 **3개** 있고, git은 이걸 **자동으로 맞춰주지 않는다.**

```
        ┌──────────────────────┐
        │  GitHub (원격 저장소)  │   ← 중앙 보관소
        └──────────────────────┘
          ↑ push   ↓ pull          ↑ push   ↓ fetch
┌────────────────────┐      ┌──────────────────────────┐
│ 내 컴퓨터            │      │ 클라우드 컨테이너 (Claude) │
│ C:\...\Macine_...  │      │ /home/user/Macine_...    │
└────────────────────┘      └──────────────────────────┘
```

1. Claude가 노트를 push하면 → GitHub에만 올라감
2. 내 컴퓨터는 그 사실을 모름 (예전 상태 그대로)
3. 이 상태에서 내가 push하면 git이 거부함: "GitHub에 네가 모르는 커밋이 있어. 덮어쓰면 날아가니까 먼저 받아와" → `rejected (fetch first)`
4. **`git pull`** = GitHub의 새 커밋을 받아서 내 컴퓨터에 합치기. 그 다음에 push

반대도 같다. 내가 push한 코드를 Claude가 보려면 Claude가 fetch해야 한다. 그래서 "push했어"라고 알려주면 받아서 본다.

> [!tip] 습관
> 공부 시작할 때 `git pull` → 코드 작성 → `git add .` → `git commit -m "메시지"` → `git push`
> (`git commit`만 치면 에디터가 열리니 항상 `-m`을 붙인다)

> [!info] PR을 만들 수 없다는 메시지
> 풀 리퀘스트는 "작업 브랜치를 다른 브랜치(보통 main)에 합쳐달라"는 요청이라 브랜치가 2개 이상 필요하다.
> 이 저장소는 브랜치가 `claude/ml-dl-learning-support-y95l9c` 하나뿐(=기본 브랜치)이라 PR을 못 만든다.
> 브랜치에 바로 push하는 방식이라 PR은 필요 없다.

## 새 세션 여는 법

1. Claude 데스크톱 앱(또는 claude.ai/code)에서 새 세션 시작
2. 환경은 **기존 환경 그대로** ("클라우드 환경 추가" 창이 뜨면 닫기)
3. 저장소 `SongDJ-coder/Macine_Learning` 선택 (브랜치가 하나뿐이라 자동으로 맞음)
4. 첫 메시지 예: "작업 브랜치는 `claude/ml-dl-learning-support-y95l9c` 그대로 써. CLAUDE.md 읽고 이어서 하자."

## 앞으로 써먹을 기능

- **설정 스크립트 확장**: 장이 넘어갈 때 필요한 패키지를 추가
- **폰으로 이어하기**: Claude 앱에서 같은 세션을 열어 이동 중에 개념 질문
- **여러 세션 병행**: 하나는 진도, 하나는 복습 퀴즈처럼 나눠서
- **예약 작업(루틴)**: 정해진 시간에 Claude가 자동으로 작업. 예: "매주 월요일 지난주 노트로 복습 문제 내기"
- **로컬 컴퓨터가 필요할 때**: 클라우드 세션은 내 컴퓨터에 접근 못 한다. Claude 데스크톱 앱에서 로컬 세션을
  열거나, 그 폴더의 터미널에서 `claude remote-control`을 실행하면 그 세션이 Claude Code 앱에도 나타난다.

## 주의할 점

- push 안 한 건 세션이 끝나면 사라진다
- GPU가 없다 → 8~9장에서 학습이 오래 걸리면 Colab이나 Kaggle을 같이 고려
- 한 세션의 대화가 너무 길어지면 무거워진다 → `CLAUDE.md`로 인계하고 새 세션을 연다
